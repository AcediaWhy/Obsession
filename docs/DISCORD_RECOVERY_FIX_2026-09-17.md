# Исправление диагностики Discord и запуска подбора

После установки релиза пользователь сообщил о зависании Discord на запуске/обновлении, ложном «Работает» в Legacy и остановке подготовки zapret2 с `baseline calibration failed at dns`.

## Подтверждённые причины

- Legacy выбирал первые два домена из hostlist, а не адреса API/обновления Discord. В списке присутствуют сторонние и вспомогательные сайты.
- Пассивный `Working` означает получение TLS ServerHello. Проекция статуса не позволяла отрицательной активной проверке снять этот статус.
- Фоновые проверки были только диагностическими, проводились раз в пять минут и не запускали восстановление при повторных сбоях HTTP после успешного TLS.
- Подтверждение кандидата Legacy допускало две неуспешные HTTP-пробы, если затем наблюдались два TLS ServerHello. В zapret2 тоже существовала возможность заменить неуспешные запросы пассивным TLS-сигналом.
- Проба zapret2 запрашивала манифест обновления без обязательных параметров платформы и принимала 4xx за успешную проверку.
- В журнале zapret2 все проверочные и контрольные домены завершились DNS-таймаутом. Первая попытка разрешения могла израсходовать весь бюджет, поэтому запланированный повтор фактически не выполнялся. Первопричина одновременного DNS-сбоя не установлена: на текущем подключении тот же код разрешает адреса успешно.

## Изменения

- Общие проверки приложения и службы используют `/api/v10/gateway` и `/distributions/app/manifests/latest?channel=stable&platform=win&arch=x64`. Требуются HTTP 200, полное тело JSON и ожидаемые поля ответа. Проба не скачивает обновления и не использует токены Discord.
- Legacy выбирает `updates.discord.com` и `discord.com` только в пределах доменов текущего проверенного конфига. Подтверждение кандидата использует те же адреса.
- Чтение HTTP ограничено временем и 256 КиБ. Заголовки, оборванное тело и зависание после заголовков не считаются успехом.
- В Legacy активная диагностика выполняется каждые 15 секунд с ротацией категорий. Два последовательных сбоя одного выбранного адреса после DNS при двух успешных независимых контрольных адресах разрешают обычный ограниченный цикл восстановления. Режимы наблюдения/подтверждения/автоматического применения и откат остаются у существующего координатора.
- Отчёты привязаны к сессии, сети, поколению датчика, реестру и поколению конфига. Устаревшие результаты отбрасываются. Одиночный сбой, DNS, HTTP 4xx/5xx, недоступность контроля или ненадёжный датчик сами по себе не разрешают подбор.
- «Работает» для Discord требует свежей активной проверки; TLS ServerHello не отменяет неуспешную проверку HTTP. Это также относится к подтверждению новых кандидатов в обоих движках.
- DNS-проверка zapret2 оставляет половину общего бюджета для второй попытки. При отказе журнал сообщает, что конфиг не оценён из-за DNS, вместо общего сообщения об ошибке калибровки.

## Проверки и границы

- Полный набор приложения: 699 тестов прошли, одна сетевая диагностика исключена из обычного запуска. Дополнительно после последней правки проверен тест отказов HTTP 400/429/500/503 и набор Environment Gate.
- Служба: 141 тест прошёл, включая повторный сбой сервера обновлений при пассивном успехе, запрет подтверждения одним TLS, истечение статуса и смену поколений.
- Сетевая диагностика выполнялась явно: манифест обновлений вернул проверенный JSON, Discord API в двух раундах завершился таймаутом, gateway ответил 404. Это частичная недоступность, а не подтверждение рабочей стратегии.
- Обнаружение доступности API и манифеста не проверяет скачивание всех файлов обновления, авторизованный WebSocket, голос, медиапотоки и все сети провайдеров. Исправленный установщик требует отдельной проверки на проблемном подключении.

## Релиз для повторной проверки

Собран штатным `npm run build:setup`, с кастомным установщиком и защищённой службой. Артефакт: `ObsessionTauri/dist-release/Obsession-Setup_1.1.0_x64-recovery-fix.exe`, 46 540 288 байт, SHA-256 `a68e8ee148c198e8ba4fcb352f9cf4795268a6d37d1cca647a1c1f506003caee`. Все 84 файла machine payload сверены с текущими release-файлами; точное включение нового payload в EXE установщика проверено. Установка на машину пользователя автоматически не выполнялась.
