# Конфиги zapret для пользователей Obsession

Исследование от 17 сентября 2026 года. Цель — подготовить обновление конфигов zapret1 и развитие пакета zapret2 для разных пользовательских сетей. Это предложение по разработке; успешность стратегий на провайдерах в рамках исследования не проверялась.

## Что есть в проекте

- Legacy: 44 файла в `ObsessionTauri/src-tauri/resources/configs`: Discord — 10, YouTube/Twitch — 10, Gaming — 15, Universal — 6, AtRisk — 3.
- `resources/manifest.json` объявляет Legacy winws 72.12. Версия исполняемого файла отдельно не проверялась.
- Zapret2: закреплённый `1.0.4-h1`, Lua API 6, пакет `builtin.base` версии 0.6.0 с 12 профилями. Это профили, часть которых работает совместно, а не 12 взаимозаменяемых конфигов.
- Есть ограниченный генератор adaptive-кандидатов, проверки TLS/QUIC, память результатов и откат. Разрабатывать всё это заново не требуется.
- Служба собирает аргументы из проверенных ресурсов. Новые конфиги нужно включать в эту схему, включая зависимости и контрольные суммы.

## Подтверждённые наблюдения

| Наблюдение | Где проверено | Что требуется |
|---|---|---|
| Discord Legacy не содержит UDP 19294–19344 | Все файлы `resources/configs/discord` | Добавить диапазон в перехват и соответствующие профили; сохранить фильтрацию `discord,stun` |
| В `gaming_1.conf` профиль UDP 1024–65535 не ограничен ipset или L7 | Последняя строка файла | Отделить целевые игровые соединения от постороннего UDP; похожие профили проверить во всём каталоге |
| Основные Twitch-домены закомментированы | `resources/lists/youtube_twitch.txt` | Явно решить область Twitch и добавить отдельную проверку воспроизведения |
| Adaptive GET заканчивает оценку на HTTP-статусе, тело ответа не читается | `adaptive_strategy/probe.rs`, `probe_target_cached` | Отдельная проверка передачи данных после рукопожатия |
| Статусы 200–499 считаются успехом HTTPS | Там же | Сохранить различие между доступностью HTTPS и пригодностью ответа для конкретного сценария |
| QUIC-проверка устанавливает соединение с ALPN h3 и закрывает его; HTTP/3-запрос не выполняется, но `https_ok` становится true | `probe_target_cached` и `probe_quic` | Разделить подтверждение QUIC-рукопожатия и реального HTTP/3-обмена |
| Проверки YouTube обращаются к главной странице и ytimg; проверки Gaming — к веб-сайтам | `targets_for` в `adaptive_strategy/probe.rs` | Не выдавать такой результат за подтверждение видео или игрового соединения |
| Discord zapret2: TLS есть на уровнях 1–4, QUIC только на уровне 4; voice/STUN отсутствуют в пакете | `strategy-packs/builtin/manifest.json` | Сделать состав поддерживаемых протоколов независимым от выбора TLS-стратегии |
| Служба выбирает профили по точному равенству `aggressiveness == level` | `runtime-service/src/zapret2_pack.rs`, `compile` | При добавлении профилей учесть точную семантику выбора; новое поле manifest само по себе ничего не изменит |
| Ограниченная поддержка voice scope уже предусмотрена валидаторами | `dpi_engine/manifest.rs`, `runtime-service/src/zapret2_pack.rs` | Можно опереться на существующую проверку портов/L7/payload |
| В `ranking.json` нет заполненного ранжирования по ASN/региону | `resources/ranking.json` | Начать с общего порядка и локальной истории, не придумывать провайдерные оценки |

Эти наблюдения не доказывают, что каждый затронутый конфиг не работает. Они показывают неполное покрытие и места, где текущая проверка не подтверждает обещанный результат.

## Что показали внешние источники

Zapret2 сохраняет в движке разбор и фильтрацию трафика, а воздействия реализует через Lua. Порядок профилей значим: выбирается первое совпадение. Поэтому перенос Legacy требует проверки поведения, а не только замены названий аргументов. [Руководство zapret2](https://github.com/bol-van/zapret2/blob/master/docs/manual.md).

Upstream blockcheck2 поддерживает повторные попытки и раздельные проверки TLS/HTTP3; для длинного HTTPS-ответа предусмотрен `CURL_HTTPS_GET=1`. Это полезный инструмент поиска кандидатов, но он не подтверждает голос Discord или игровой сеанс. [Руководство blockcheck2](https://github.com/bol-van/zapret2/blob/master/docs/manual.md#blockcheck2).

Официальная Windows-сборка содержит blockcheck для обоих движков. Его нужно запускать при остановленных других средствах DPI-обхода. [zapret-win-bundle](https://github.com/bol-van/zapret-win-bundle).

В актуальных примерах Flowseal есть Discord UDP 19294–19344 и 50000–50100, отдельные TLS-профили discord.media, варианты перекрытия сегментов и модификации TLS fake. Это источники кандидатов для адаптации, а не доказательство работы на всех сетях. [general.bat](https://github.com/Flowseal/zapret-discord-youtube/blob/main/general.bat), [FAKE TLS AUTO](https://github.com/Flowseal/zapret-discord-youtube/blob/main/general%20%28FAKE%20TLS%20AUTO%29.bat).

В upstream доступен zapret2 1.0.5.2 от 15 сентября. Его заметка сообщает об оптимизации выбора профилей; сам номер версии не гарантирует улучшение обхода. В Obsession есть собственные патчи для 1.0.4-h1, поэтому обновление движка требует отдельного переноса патчей и проверки воспроизводимой сборки. [Релиз](https://github.com/bol-van/zapret2/releases/tag/v1.0.5.2), локально — `ObsessionTauri/third-party/zapret2`.

## Предлагаемая модель каталога

Единица разработки: сервис/сценарий + транспорт + семейство стратегии + область применения + проверенные зависимости. Пользователь по-прежнему может выбирать понятные категории; внутри полезно разделить:

| Сценарий | Транспорт | Достаточное подтверждение |
|---|---|---|
| Discord: интерфейс/API/загрузки | TLS | Нужные ответы API и ограниченная загрузка |
| Discord: gateway | TLS + WebSocket | Установление WebSocket, а не только HTTPS главной страницы |
| Discord: голос | UDP, Discord discovery/STUN | Соединение с реальным голосовым сервером и двусторонний звук |
| YouTube | TLS и QUIC отдельно | Получение реального медиасегмента, затем воспроизведение |
| Twitch | TLS/доступный транспорт медиасервиса | Плейлист и медиасегменты, затем воспроизведение |
| Игровой лаунчер/API/CDN | TLS/QUIC | Авторизация или доступный публичный эквивалент, загрузка |
| Игровой сеанс | Протокол конкретной игры | Подключение к серверу, устойчивость и задержка |

STUN-ответ сам по себе не подтверждает голос. Успех GitHub или сайта игры не подтверждает игровой UDP. Для проверок с учётной записью нужна пользовательская сессия; автоматическая публичная проверка должна честно оставлять такой сценарий непроверенным.

Для TLS первоначально достаточно нескольких различающихся семейств: чистое разбиение, переупорядочивание, fake с разбиением/переупорядочиванием, fakedsplit/fakeddisorder, hostfakesplit там, где это поддерживают движок и валидаторы. QUIC и голос получают отдельные наборы. Повторы fake, позиция split и способ отбрасывания fake сервером — параметры семейства, а не основание создавать десятки почти одинаковых пресетов.

Число repeat или условная «агрессивность» не задают универсального порядка качества. Предлагаемый порядок: подтверждённая история этой сети, стабильность нужного сценария, отсутствие регрессий, затем задержка и накладные расходы.

Для zapret2 нужно выбрать один механизм переключения стратегий. На первом этапе разумно оставить управление существующему Rust adaptive. Подключение Lua circular одновременно с ним требует отдельного согласования состояний и учёта фактически исполняемой стратегии.

## Порядок работ

1. **Инвентаризация и статическая проверка.** Составить машинный реестр всех профилей: фильтры, порты, списки, blobs, версия движка, происхождение. Проверять покрытие capture-фильтрами, существование ресурсов, порядок профилей, область высоких портов, дубли и синтаксис на закреплённом бинарнике. Отдельно проверить смысл сочетания hostlist и ipset в одном профиле.
2. **Точечное обновление Legacy.** Discord UDP, состав Twitch, область Gaming и актуальность списков. Затем добавить небольшой набор новых кандидатов из upstream/Flowseal с указанием commit и лицензии. Сохранить старые идентификаторы для настроек и отката.
3. **Усиление проверок.** Добавить чтение ограниченного объёма тела и отдельные результаты для сервиса и транспорта. Проверять таймаут посреди ответа; различать «сервер ответил 403» и «медиа успешно загружено».
4. **Пакет zapret2 следующей версии.** Сформировать полноценные наборы TLS/QUIC/voice. На старой схеме каждый уровень обязан явно включать требуемые профили; предпочтительная следующая схема разделяет общие профили и выбранный вариант. Обновить оба компилятора/валидатора и подготовку ресурсов согласованно.
5. **Проверка на разных сетях.** Домашние и мобильные подключения, несколько операторов и регионов, IPv4/IPv6, разные клиенты. Подтверждённость на одной линии хранить отдельно от готовности общего пакета.
6. **Выпуск с откатом.** Публиковать версии конфигов, списков и движка с понятной совместимостью. Новая версия не должна автоматически стирать сохранённый рабочий результат пользователя; перед применением нужна повторная проверка его актуальности.

## Предлагаемый протокол испытаний

- Зафиксировать версию движка, пакет, hash стратегии, состав списков, клиент, транспорт и семейство IP.
- Сначала проверить исходную доступность и независимые контрольные адреса. Отличать DNS, TCP, TLS, ответ HTTP и передачу тела.
- Для отбора использовать короткие серии повторов; для финалистов — более длинные серии и повтор позже. Стартовые числа 3 и 10 — параметры методики, а не гарантия статистической надёжности.
- Для выявления обрывов после первых килобайт читать заранее выбранный ресурс существенно больше 16 КБ с ограничением размера и времени. Порог, например 256 КБ, — проектное предложение; ресурс должен реально отдавать нужный объём.
- Использовать реальные доступные медиаресурсы; не считать `rr1---sn.googlevideo.com` из metadata пакета достаточной проверкой YouTube.
- Проверять незатронутые сайты, DNS, звонки и игровые приложения на побочные эффекты. Ограничивать частоту запросов, учитывать 429 и ошибки самого сервера.
- Результат: раздельные статусы «не проверено», «не поддерживается», «частично работает», «подтверждено для данного сценария и сети».
- Для распространения собирать добровольные обезличенные отчёты. Не добавлять автоматическую телеметрию в продукт с заявленным отсутствием её сбора.

## Границы исследования

Рабочие конфиги, код службы, сетевые настройки и бинарники не изменялись. Blockcheck и испытания на реальных сетях не запускались. GitNexus оказался устаревшим; попытка обновления завершилась `Failed calling LOWER: Invalid UTF-8`. Поиск по индексу доступен, но context выдаёт дубли символов. Наблюдения выше проверены по исходным файлам; перед будущими изменениями функций необходимо восстановить достоверный impact analysis согласно AGENTS.md.
