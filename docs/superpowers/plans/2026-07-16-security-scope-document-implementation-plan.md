# План реализации Security Scope

**Цель:** добавить в корень репозитория русскоязычный `SECURITY_SCOPE.md`,
который точно описывает назначение, security-sensitive возможности и защитные
границы Obsession.

## Этап 1. Сопоставить утверждения с проектом

1. Использовать README и актуальные Adaptive Zapret2 specifications как источник
   описания возможностей.
2. Проверить защитные утверждения по текущему коду: Safe DSL, allowlist,
   bounded search, SHA-256, certificate verification, rollback и минимальные
   логи.
3. Не включать обещания или ограничения, которые нельзя подтвердить проектом.

## Этап 2. Создать SECURITY_SCOPE.md

1. Описать назначение и допустимую область применения.
2. Перечислить фактические сетевые и системные возможности.
3. Явно перечислить отсутствующие возможности и действия вне scope.
4. Зафиксировать ограничения Adaptive Zapret2, привилегий, данных и ресурсов.
5. Описать fail-closed, rollback и ручное подтверждение.
6. Добавить контекст для AI-ревьюеров и правила допустимого использования.

## Этап 3. Проверить документ

1. Сверить структуру с утверждённой спецификацией.
2. Проверить отсутствие `TODO`, `TBD` и двусмысленных обещаний.
3. Убедиться, что документ не является инструкцией по разработке новых техник
   обхода и не скрывает существующую функциональность.
4. Выполнить `git diff --check`.

## Этап 4. Зафиксировать результат

1. Добавить только `SECURITY_SCOPE.md` отдельным коммитом.
2. Не включать несвязанный локальный `install.ps1`.
