# Discord: сборка двух профилей и плавное завершение анимации

Сборщик объединяет два проверенных именованных TLS-профиля в одном процессе winws2:
один обслуживает обычный список Discord с исключёнными CDN-доменами,
другой — только фиксированные CDN-домены. Последовательности действий родителей
сохраняются целиком. QUIC и голос остаются отдельными профилями.

Список ролей и проверка совместимости находятся в
`runtime-protocol/src/zapret2_composition.rs` и используются приложением и службой.
IPC передаёт только идентификаторы двух родителей. Вложенные сборки, неизвестные
профили, чужие категории, эксперименты и неподдерживаемые фильтры отклоняются.
Служба проверяет конфигурацию до остановки текущего процесса.

Механизм использует штатные фильтры
[`--hostlist-domains` и `--hostlist-exclude-domains`](https://github.com/bol-van/zapret2/blob/master/docs/manual.md#фильтрация-по-листам).
Разделение действует по имени хоста, а не по URL внутри зашифрованного соединения.
Файлы `discord.com/assets/...` проверяются с профилем API; CDN-пробы проверяют CDN-профиль.

## Автоматический режим

Если готовый кандидат полностью проходит пробы, турнир проверяет его повторно.
Если полных результатов нет, но два кандидата дополняют друг друга по API/Gateway
и CDN, сборщик повторно проверяет их полезные области. Все записанные результаты
области должны быть положительными, сопоставимыми и содержать необходимые TLS-пробы.
Нужно минимум два независимых раунда на область.

Один подбор предлагает не больше одной сборки. Только при дополняющих результатах
разрешаются три дополнительных замера. Лимиты времени 90/180/300 секунд сохраняются.
Сборка имеет отдельный fingerprint и проходит собственные полные замеры: два для
«Быстро»/«Баланс» и три для «Глубоко». Результаты родителей в её подтверждение не входят.
Два отказа, общий провал CDN, противоречивые повторы и неопределённая сеть успехом не становятся.

## Явное испытание

После установки новой сборки: Discord → «Настройки и результаты» → «Сборка Discord».
Выбрать разные профили для API/Gateway и CDN, нажать «Проверить сочетание».
Этот путь проверяет выбранную пару даже когда готовый профиль работает.
Автоматическое применение отсутствует: после каждого замера возвращается исходная
конфигурация, а «Применить TLS» появляется только для подтверждённого результата.
Действуют прежние проверки актуальности сети, настроек, поколения runtime и рецепта.

Для первого испытания можно взять `research_discord_tls_hostfake_md5` для API/Gateway
и `classic_discord_tls_split_sni` для CDN. Это тест маршрутизации сочетания;
эффективность именно этой пары на пользовательском провайдере пока не подтверждена.
Родителей и собственные замеры сборки видно в раскрытых подробностях результата.
Запуск приложения и голос по-прежнему требуют отдельных испытаний.

## Анимация

После завершения сохраняется время на складывание силуэта. Затем сцена затухает
за 950 мс, а занимаемое место сворачивается за 850 мс с задержкой 450 мс.
Удаление компонента происходит после переходов. Новый подбор отменяет таймеры;
при отключённом движении и скрытом окне удержание сцены не выполняется.
Фаза проверки сочетания отображается как «Проверяем сборку…» с частичным силуэтом.
При нулевом размере сцена приостанавливается и возобновляется после изменения
размера. Пустая маска силуэта получает запасную точку, чтобы переключение
«Без движения» не останавливало отрисовку из-за отсутствующих координат.

## Проверки и границы результата

- 66 тестов Zapret2 приложения; два живых сетевых теста оставлены opt-in.
- 37 тестов протокола, 15 тестов Zapret2 службы.
- 503 теста интерфейса; production build и native release build.
- Реальная служебная компиляция/материализация двух сочетаний с обратными ролями;
  оба конфигурационных набора принял поставляемый winws2 с `--dry-run`.
- Браузерный замер затухания, сворачивания места и блокировки одинаковых родителей.
- Повторное переключение движения в браузере без ошибок отрисовки; два теста
  нулевого размера и пустой маски силуэта.
- Проверка встроенного payload, файловых хешей и подписи update manifest.

Тесты расписания используют искусственные результаты. Нативный парсер запускался
без захвата трафика. Установленная служба и текущая DPI-сессия не менялись:
живое испытание составного кфг на провайдере остаётся следующим шагом.
Подробности: `ZAPRET2_DISCORD_COMPOSER_BUILD_2026-10-06.json` и
`ZAPRET2_DISCORD_COMPOSITION_PARSER_2026-10-06.json`.
