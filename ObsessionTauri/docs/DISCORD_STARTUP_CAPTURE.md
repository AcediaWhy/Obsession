# Один запуск настоящего Discord

Из корня проекта запустить `Discord-Startup-Diagnostic.cmd`. Discord перед
запуском должен быть полностью закрыт через трей, Zapret2 в Obsession включён,
VPN выключен. Дождаться загрузки Discord и полностью завершить его через трей,
затем дождаться результата в окне диагностики. Если клиент не загрузится за
120 секунд, также завершить через трей. Сообщить, открылся ли клиент и сколько
примерно пришлось ждать. Во время
записи не запускать подбор/диагностический контроль в Obsession.

Скрипт запускает установленный Discord Stable с `--log-net-log`.
Он не завершает клиент автоматически и не меняет
конфиг/сетевые настройки. Отдельная установка Obsession не требуется.
Результаты остаются в git-ignored `.dev-logs/discord-startup/<session>/`:
`netlog.json`, локальные stdout/stderr клиента и короткий технический
`capture.json`. Окно диагностики держать открытым до сообщения о результате.
Ожидание сборщика ограничено 140 секундами; это не автоматическая остановка
NetLog, который завершает запись при нормальном выходе из Discord.

Если файл не создался/не завершился, скрипт сообщает об этом; результат
`missing_or_incomplete` не является диагнозом сетевого отказа Discord.
При таком результате завершить Discord через трей, чтобы остановить/дописать
возможный журнал. Работающий процесс не перезапускается: если Discord уже
открыт, скрипт останавливается с инструкцией закрыть его вручную.

Используется стандартный режим приватности NetLog без IncludeSensitive или
Everything. Это не гарантия отсутствия личных данных: исходный журнал хранится
только локально; его нельзя коммитить, выкладывать или печатать целиком.
Для разбора нужны только события, адреса и время сетевых этапов нужного Gateway,
без cookies, заголовков авторизации, READY payload и идентификаторов аккаунта.

Основания: [Electron command-line switches](https://www.electronjs.org/docs/latest/api/command-line-switches#--log-net-logpath)
и [Chromium NetLog startup capture](https://www.chromium.org/for-testers/providing-network-details/).
`--net-log-duration` документирован для Chromium с M137. В установленном `app-1.0.9260/Discord.exe`
03.10.2026 найдены строки `log-net-log`, `net-log-duration`, `net-log-capture-mode`;
это предварительная проверка наличия переключателей, ещё не доказательство
успешной записи или автоматической остановки именно этим приложением. После
первого сбора обещание автоматической остановки отозвано: три файла пусты,
один оборван, итоговые capture.json остались в начальном состоянии. Пользователь
подтвердил, что несколько раз закрывал окно, опасаясь неработающего обхода;
последний запуск открылся. Нельзя по этим данным доказать поддержку автоflush
или назначить единственную причину потери всех файлов. Исправленный сборщик
не полагается на этот переключатель и обновляет metadata во время записи.
Скрипт проверяет наличие завершённого
JSON с constants/events перед объявлением успеха.

Проверка без запуска приложения/создания журнала:
`powershell.exe -NoProfile -File scripts/capture-discord-startup.ps1 -Preflight`.

Локальный безопасный разбор полного/оборванного NetLog:
`node scripts/analyze-discord-startup.mjs path/to/netlog.json [safe-output.json]`.
Он сохраняет признак неполного журнала и выводит только SNI публичного сервиса,
числовые тайминги/ошибки, адреса и структурные параметры ClientHello. Содержимое
заголовков, cookies, токены, clientInfo и исходные handshake bytes не выводятся.
