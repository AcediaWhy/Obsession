# Разбор первого сетевого теста flow-programs-v9

Источник: `measurement-20261002T182717.216972100Z-27088-0.jsonl`, 2026-10-02 22:27–22:28 Europe/Samara. Policy `adaptive_owned_flow_programs_v9`, deep, 90 с, подбор с нуля. Работа в браузере не измерялась.

- 7 попыток, 0 рабочих вариантов, итог `probe_unreliable`, 61.087 с с проверками и возвратом. Исходный конфиг точно возвращён; HTTPS на нём до и после теста не проходил.
- В попытках 1, 2, 4, 5, 6 новая программа подтверждённо вызывалась на двух основных проверочных сокетах. Send API не сообщил ошибки; packet capture полон. После ClientHello ACK-offset 0, ServerHello нет. Это наблюдение не доказывает доставку преобразованных пакетов на физический интерфейс и не устанавливает конкретную причину молчания сети.
- Программы: multidisorder → multisplit с теми же границами, clone+fake, hostfakesplit, fakedsplit → fakeddisorder, fake с TTL 5. Два изменения порядка действительно выбраны по flow feedback. Их одинаковый неуспех не доказывает, что дальнейший синтез обязательно найдёт обход.
- Попытка 3 содержала `tls_client_hello_clone` + `fake`. В receipt найден `flow_rejected|…|invalid_plan`. Причина — собственная опечатка allowlist исполнителя: `tls_clienthello_clone` вместо настоящего `tls_client_hello_clone`. Программа продолжалась через штатную цепочку, но новая привязка исполнения не работала; planner справедливо не обучался на таком результате.
- В попытке 7 обе основные TCP connect проверки уже не установили соединения. Поиск остановился после возврата. Причина изменения сетевого состояния пока не установлена.

Исправлено в pack 0.9.1: точное имя оператора. Добавлена регрессия на реальной штатной цепочке clone+fake, с реальным Lua-модификатором SNI и отправкой клонированного blob; только нативные TLS dissect/reconstruct/send функции заменены инертными fixtures. Проверка прошла на обеих Lua API surfaces и настоящем LuaJIT 2.1. Успех на сети после исправления ещё не проверен.

Интерфейс: длинные объяснения удалены, тесты свернуты под «Тесты и отчёты», сравнения — в отдельном раскрываемом блоке. Подписи короче; пояснения к действиям доступны по наведению. IPC и режимы тестов сохранены.

Следующий этап должен проверять действие каждого оператора, расширять причинный синтез и отделять отказ конкретного TLS-преобразования от изменений TCP-пути/состояния сети. Смена программ без перезапуска уменьшит накладные расходы, но сама по себе не гарантирует успешный обход. Реальные WSS/voice/CDN остаются отдельной задачей.
