# Сравнение рабочего состояния и отказа Discord

Цель — измерить одни и те же конфиги на одних и тех же адресах в двух
моментах времени. Успех повторяемости 17:13 подтвердил bypass против
passthrough, но исходный конфиг работал уже до поиска. Отказ 16:56 остался
необъяснённым. Новое измерение отделяет смену кандидата и DNS от времени.

## Действия пользователя

1. Установить сборку fixed-comparison. Выключить VPN. Когда Discord работает,
   открыть Discord → TLS → диагностика, отметить «VPN отключён, готов к
   измерению» и нажать **«Зафиксировать сравнение»** один раз.
2. Дождаться возврата исходного конфига. Если понадобится, открыть Discord
   вручную: тест измеряет HTTPS, не выполнение приложения и голос.
3. Когда при тех же настройках и подключении Discord снова перестанет
   работать, выключить VPN, отметить готовность и нажать
   **«Повторить то же сравнение»** один раз. Не создавать новую пару в этот
   момент: это заменит сохранённые адреса.
4. Передать два отчёта. Они связываются полем fixed_comparison.anchor.id.

Два последовательных запуска в рабочем состоянии не заменяют измерение
во время реального отказа. Если отказ больше не появляется, он не измерен.

## Что фиксируется

- Кандидат из последнего завершённого подтверждённого сравнения Discord/TLS,
  с совпадающими engine_version и scope_fingerprint. Незаконченный отчёт,
  failed restore, неполные раунды и inconclusive не становятся источником.
- Текущий launch snapshot без runtime generation: выбор профилей и overrides.
- Один подготовленный системой IP для discord.com и gateway.discord.gg,
  предпочтительно IPv4, порт 443. Только фиксированные диагностические
  authorities, без локальных адресов и произвольных портов.
- Порядок трёх пар candidate/passthrough с обязательными AB и BA.
- Хеш runtime manifest и приложения, хеш исходного отчёта, дата и ID пары.

Сохраняется файл `discord-fixed-comparison-v1.json` в локальной папке
диагностики. Запись атомарная. Это fixture измерения; она не применяется
как постоянная рекомендация. Повтор не обращается к новой DNS подготовке,
не запускает portfolio и не меняет кандидата. Изменившиеся настройки,
списки, manifest или бинарник приложения требуют новой пары.

## Измерение и ограничения

До сравнения текущий конфиг измеряется в двух полных раундах. Затем идут
шесть блоков candidate/passthrough, по два полных HTTPS раунда в каждом,
с перезапуском обеих сторон, свежими no_proxy клиентами, закреплёнными
адресами, независимыми HTTPS контролями и снимками маршрутов.
Отказ кандидата не отменяет сбор остальных блоков.

В фиксированном режиме каждый блок одновременно получает дополнительные
TCP/TLS-пробы на тех же адресах. Их local/remote socket сопоставляются с
service-owned packet metadata в effect_validation_runtime:
supplementary_tls и packet_probe_correlation. Это отдельные соединения;
ServerHello не заменяет успех HTTPS. Потери capture запрещают отрицательный
вывод по отсутствию пакета. Порядок обработки и physical wire delivery
не удостоверяются. Lua trace windows ограничены и могут быть усечены.

На шесть блоков выделяется 120 секунд; проверки исходного конфига,
подготовка и завершение возврата дополнительно занимают время.
Отмена дожидается завершения принадлежащей тесту смены runtime. После
сравнения возвращается точный исходный launch и снова измеряется двумя
раундами на сохранённых адресах. Внешняя смена generation блокирует
присвоение чужого состояния и его откат.

Маркер протокола: fixed_cross_session_comparison_v1. Каждый отчёт содержит
полный anchor, replay, search_performed=false и reference provenance.
Конфиг, адреса и порядок в двух отчётах должны совпадать по anchor ID.
Разница результатов даёт наблюдение временной нестабильности при этих
фиксированных входах, но не устанавливает виновника. Один и тот же IP
не удостоверяет неизменность физического сетевого пути. WSS, голос,
исполнение браузерного приложения и межсессионное обучение не измерены.

Проверены 225 adaptive tests (2 внешних integration tests исключены),
включая фактический prepare(replay), ошибки fixture/config/resources,
выбор источника и handoff без apply/persist/search. Проверки UI, store
и API contract: 35 passed. Сетевой запуск нового режима ещё не выполнен.
