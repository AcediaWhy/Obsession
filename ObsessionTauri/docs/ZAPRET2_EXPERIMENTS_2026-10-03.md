# Два локальных эксперимента Zapret2

> Историческое описание сборки от 3 октября. В исправленной сборке от 4 октября возвращены отдельные карточки сервисов и подбор. ClientHello выбирается явно в TLS-списке Discord; прежний глобальный переключатель при миграции отключается. См. `ZAPRET2_SERVICE_RESTORE_2026-10-04.md`.

Это реализация направлений 1 и 2 из `ZAPRET2_CONCEPTS_2026-10-03.md`. Профиль ClientHello доступен для ручного включения в Obsession; TLS record fragmentation поставляется отдельным локальным прототипом. Новый подбор, история рекомендаций и автоматическая замена конфигураций не добавляются.

## ClientHello в Obsession

В разделе DPI → Zapret2 есть отдельная кнопка **ClientHello · тест**. Она по умолчанию выключена и доступна при выбранном Discord и остановленном обходе. Включение сохраняет номер выбранного набора 1–4 и заменяет только его TLS-профиль Discord. Voice, QUIC и остальные категории используют выбранные обычные правила. Повторное нажатие возвращает стандартный TLS-профиль того же набора.

Профиль определён отдельно в `manifest.experiments`; исходные 19 элементов `manifest.strategies` сохранены. Новый Lua-файл, manifest и зависимости проходят ту же проверку целостности и защищённую сборку argv, что и обычные профили. IPC передаёт только булев выбор; caller не может передать свой Lua-код, пути, blobs или retired adaptive overrides.

На одном полном распознанном ClientHello размером до 8192 байт:

1. Создаётся копия текущего запроса с заменой списка SNI на `www.google.com` штатной Lua-функцией upstream. Настоящий ClientHello не изменяется.
2. Фейк отправляется один раз по потоку с TCP sequence, смещённым на −16384. Его байты находятся до диапазона настоящего сообщения. TTL, checksum, ACK и timestamps не подменяются.
3. Оригинал сегментируется штатным MSS-aware multisplit по `2,midsld`. Это фиксированные правила исполнения; механизм не ищет кандидатов.

Исправление от 4 октября: числовые CLI-маркеры — смещения байтов с нуля. Разрез `2` отделяет два байта; `pos=1` отделяет один байт и влияет на поведение. При обычном вызове C-обёртка прибавляет единицу для индекса Lua. `delete_pos_1` удаляет нулевое смещение, а не числовой CLI-маркер `1`. Проверено по исходникам закреплённого [protocol.c](https://github.com/bol-van/zapret2/blob/v1.0.5.2/nfq2/protocol.c) и [lua.c](https://github.com/bol-van/zapret2/blob/v1.0.5.2/nfq2/lua.c). Параметры сохранённых правил при переносе не упрощаются.

Повторные передачи не создают дополнительные фейки. При неполной сборке, неизвестном формате или отсутствии conntrack оригинал проходит без этой трансформации. Ошибка отправки оригинальных сегментов не должна приводить к потере оставшихся исходных частей replay. Уже раздробленный на несколько TLS records ClientHello этот профиль не преобразует.

Отбрасывание фейка серверным TCP-стеком и его обработка конкретным DPI — отдельные свойства сетевого пути. Вызов rawsend, parser dry-run и локальная модель доставки не доказывают физическую передачу пакета или выигрыш против ТСПУ.

Для этой функции нужны новая сборка приложения и соответствующая защищённая служба/ресурсы. Обычный запрос с выключенной опцией сохраняет прежний JSON-контракт. Запрос с включённой опцией старой службой отклоняется; изображать активный эксперимент поверх старого runtime нельзя.

## TLS record fragmentation

`obsession-tls-record-proxy.exe` — локальный TCP-адаптер с одним явно заданным IP:port и ожидаемым SNI. Он принимает готовый TLS от клиента, собирает первый ClientHello и заново оборачивает те же handshake-байты в несколько TLS records. Одна граница проходит внутри hostname SNI; остальные ограничиваются выбранным размером фрагмента.

TLS остаётся между исходным клиентом и сервером: адаптер не имеет ключей сессии, не устанавливает root certificate и не расшифровывает HTTPS. После первого ClientHello поток передаётся в обе стороны, включая зашифрованные данные и half-close. Сертификат сервера по-прежнему проверяет клиент.

Прототип:

- Слушает только `127.0.0.1` или `::1`; допускает один фиксированный числовой адрес назначения.
- Проверяет совпадение SNI до открытия исходящего соединения.
- Ограничивает число подключений, объём сборки и время ожидания.
- Не устанавливает системный proxy, не меняет DNS/hosts/routes и не запускает драйвер DPI.
- Не обслуживает HTTP CONNECT/SOCKS. Обычный Discord нельзя направить через него одним `--proxy-server`: для этого потребовалась бы отдельная интеграция маршрутизации/прокси. Сейчас он пригоден для изолированных клиентов, которым можно явно задать TCP endpoint с сохранением TLS server name.

По умолчанию: до 16 одновременных соединений, первый ClientHello ≤65536 байт, TLS record ≤16384 байт, не более 256 входных records; 5 секунд на ClientHello/connect, 60 секунд простоя и 300 секунд жизни соединения. По истечении пяти минут закрывается даже активный WSS. Это ограниченный стенд; постоянный Gateway WSS через него не подтверждён. Совместимость record fragmentation с новым clone-профилем также не проверена.

### Ручной запуск

Пример требует актуального числового адреса выбранного сервера. IP указывается пользователем; скрипт сам DNS не перенастраивает и адреса не подбирает:

```powershell
.\scripts\Start-TlsRecordPrototype.ps1 -ServerName discord.com -TargetAddress <IPv4-или-IPv6>
```

В распакованном `Zapret2-TlsRecords-Prototype_2026-10-03.zip` скрипт находится рядом с exe: используйте `./Start-TlsRecordPrototype.ps1` с теми же параметрами. Архив содержит контрольные SHA256 для бинарника, скрипта и документации.

В другом терминале можно проверить HTTPS через тот же адрес, сохранив проверку сертификата `discord.com`:

```powershell
curl.exe --noproxy "*" --connect-to "discord.com:443:127.0.0.1:18443" "https://discord.com/" --max-time 20
```

Если требуется другой порт назначения, задаётся `-TargetPort`; `-ListenPort` и `-FragmentBytes` меняют локальный порт и максимальный размер записи. Ctrl+C завершает адаптер и его соединения.

Успех этого HTTPS-запроса относится к выбранному endpoint и запросу. Готовность Discord API, Gateway, CDN, аккаунтной сессии и голоса проверяется отдельно настоящим клиентом.

### Сборка и локальные проверки

```powershell
cargo test --manifest-path tls-record-proxy/Cargo.toml --locked --offline
cargo build --manifest-path tls-record-proxy/Cargo.toml --release --locked --offline
```

Тесты используют только loopback, свежий локальный тестовый сертификат и созданные тестом сообщения. Частные Discord NetLogs, key shares из прошлой диагностики, токены и аккаунтные данные не используются.

Для clone-профиля прошли 78 офлайн-проверок с настоящими bundled Lua-функциями парсинга/клонирования/отправки и сегментации. В том числе четыре свежих TLS 1.2/1.3 handshake с проверкой сертификата, Finished и HTTP в MemoryBIO-модели. C-маркеры позиции и rawsend заменены тестовыми адаптерами; серверное отбрасывание старого sequence моделируется. Эти результаты не доказывают поведение физического TCP-стека или WinDivert.

Для record-адаптера прошли 11 локальных интеграционных тестов: свежие TLS 1.2/1.3 с проверкой сертификата и Finished, HTTP-запросы 200 KB/ответы 400 KB, half-close, bytewise/многозаписный ClientHello, WSS upgrade с ping/pong, native Windows curl с `--connect-to`, отказы по SNI/формату и ограничения ресурсов. `cargo clippy --all-targets -- -D warnings` прошёл.

## Критерий дальнейшей разработки

После локальной проверки корректности нужен ручной сравнительный запуск на целевом подключении: те же рабочие настройки, обычный и экспериментальный TLS-профиль, несколько новых реальных запусков, время до готовности и повторное подключение. Отдельный удачный handshake не считается подтверждением долгосрочной устойчивости.

Результаты проверок и хэши конкретных сборок записываются отдельно в release receipt. Сетевой выигрыш против ТСПУ не объявляется по результатам локального стенда.
