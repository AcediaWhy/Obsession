# Проверка составной конфигурации Discord

Испытатель `zapret2-functions-v5-routing` разделяет два факта: публичный запрос
получил проверенный ответ; его точное TCP-соединение обработал выбранный блок
winws2. Для подтверждения TLS-кандидата теперь необходимы оба факта во всех
обязательных пробах каждого раунда. Это действует и для готовых профилей.

## Что исправлено

- Явное испытание пары выполняет два раунда для «Быстро»/«Баланс» и три для
  «Глубоко», даже после первого неполного результата. Все результаты остаются
  в истории. Один отказ или неопределённый результат не стирается последующими
  успехами и не позволяет объявить всю серию подтверждённой.
- Составной профиль остаётся единственным кандидатом явного испытания.
  Готовый профиль не может стать его победителем. Автоматический сборщик
  по-прежнему проверяет родителей и затем отдельно испытывает саму сборку.
- Обычные HTTP-пробы и загрузка файлов используют принадлежащие испытателю
  сокеты с новым TLS-сеансом и проверкой сертификата. Предварительное TCP-
  соединение с последующим независимым подключением reqwest убрано. Для
  обеих форм большого ClientHello сохраняются два собственных соединения.
- Gateway отдельно отмечает TCP, TLS, WebSocket Upgrade и Hello. Тайм-аут
  на TLS больше не записывается как неопределённый этап «websocket».
- Служба добавляет наблюдатель перед действиями каждого выбранного профиля.
  Для исходящего ClientHello он сохраняет идентификатор блока, точные локальный
  и удалённый IP/порт, завершённую Lua-функцию и успешный результат native send.
  Повторы одной записи не заполняют буфер. SNI, содержимое пакетов и сеансы
  Discord не записываются. Форма метаданных соответствует
  [Lua API zapret2](https://github.com/bol-van/zapret2/blob/master/docs/manual.en.md#the-dis-table-structure).
- Записи запрашиваются у службы для точного поколения тестового процесса
  до его остановки/восстановления исходного профиля. У каждой пробы сохраняются
  `connections`: ожидаемый и наблюдавшийся профиль, действия, принятые отправки
  и результат сверки. API/Gateway и файлы на discord.com требуют API-родителя;
  CDN-соединения требуют CDN-родителя.
- Чужой порт, чужое поколение, другой профиль, `unmatched`, ошибка Lua/send,
  отсутствие отправки или обрезанная диагностика блокируют подтверждение.
  Данные без маршрутизации остаются неподтверждёнными. Подробности пишутся
  в `zapret2-trials.json` и диагностическую часть `logs/app.log`.
- Интерфейс показывает подтверждение обработки блоками отдельно от ответов
  сервисов. Применение требует свежих раундов v5 с собственной маршрутизацией;
  старые v4-результаты доступны как история. Исходный сохранённый профиль
  не меняется самим испытанием.

## Проверки и границы

Проверки расписания, выбора победителя и отрицательных вариантов маршрутизации
используют явно искусственные результаты. Они проверяют правила допуска,
а не работоспособность обхода. Среди отрицательных вариантов — все HTTP-пробы
зелёные, но обработал исходный профиль; копия поколения; нет записи native send;
нет свежей диагностики; первая проба неполная, две последующие успешны.

Сетевые проверки TLS/HTTP и TLS/WebSocket запускают настоящие локальные серверы
и соединения, проверяют сертификат/SNI/Host, ответ и идентичность сокета. В них
не участвуют WinDivert и DPI провайдера. Проверка Lua выполняется на настоящем
LuaJIT 2.1, но сетевые примитивы в ней заменены инертными тестовыми функциями.
Проверка парсера winws2 использует только `--dry-run`: она не проверяет захват
трафика или эффективность конфигурации. Эти результаты не переносятся
в историю пользовательских испытаний и не создают разрешение на применение.

Положительный результат v5 означает: выбранные блоки выполняли Lua-действия,
native API принимал отправки для точных соединений, обязательные ответы
подтвердились повторно. Он не доказывает доставку изменённых пакетов по проводу,
необходимость обхода, преимущество сборки над готовым профилем, авторизацию
клиента Discord или голосовой вызов. Авторизация и голос остаются отдельными
сценариями. При заполнении диагностического буфера результат консервативно
теряет подтверждение, даже если сохранены отдельные положительные записи.
