# Исправление адресации и времени подбора Zapret2

Дата: 4 октября 2026 года. Повод: пользовательский подбор Discord TLS завершился без рабочего результата за 118,237 секунды.

## Что показали факты

В сохранённом прогоне было 7 кандидатов. REST API Discord у всех ожидал почти полные 15 секунд. У `discord_tls_multidisorder_alt` и `research_discord_tls_window_disorder` Gateway, CDN и updater при этом проходили за доли секунды. Отказ API не позволял подтвердить весь профиль.

Отдельная проверка TCP без DPI обнаружила недоступный `162.159.136.232:443`, тогда как четыре других адреса `discord.com` отвечали за 47–110 мс. Старый тестер сначала резолвил имя для проверки наличия адреса, затем позволял HTTPS-клиенту резолвить его заново без собственного короткого ограничения подключения. Это оставляло возможность провести весь раунд в ожидании одного недоступного адреса.

Точный адрес прежних зависших запросов не был записан. В последующем сравнении старый запрос тоже получил HTTP 200 через `162.159.135.232`. Поэтому причина всех прежних таймаутов не считается полностью установленной; условия сети и набор выбранных адресов могли различаться. [Сохранены исходные результаты и сравнение](ZAPRET2_PICKER_FIX_RECEIPTS_2026-10-04.json).

## Исправление

- До восьми системных DNS-адресов проверяются с ограниченным TCP-подключением и задержкой 80 мс между попытками. Одна недоступная цель не удерживает остальные. Все попытки принадлежат отменяемой future.
- HTTPS-клиент закрепляет выбранный доступный адрес. URL, Host, SNI и проверка сертификата сохраняются. DNS/hosts/маршруты ОС не изменяются. Для HTTP создаётся новое соединение с выбранным адресом; WSS продолжает уже установленное TCP-соединение.
- Первичный отбор получает 3 секунды на сетевые пробы кандидата. Повторное подтверждение получает 4 / 6 / 8 секунд для режимов «Быстро» / «Баланс» / «Глубоко».
- После завершения всех обязательных проб раунд заканчивается. Ожидание вспомогательного сайта или updater прекращается с явным неопределённым/неиспытанным результатом, без объявления успеха.
- Лимиты остались 3 / 5 / 7 попыток и 2 / 2 / 3 полных подтверждения. Возврат исходного runtime и запрет применения неподтверждённых результатов сохранены. Общий бюджет включает запуск и худший предусмотренный возврат; 3 секунды — предел сетевой части первичного отбора, а не всего подбора.
- Версия автоматического тестера повышена до `zapret2-functions-v2`; интерфейс поясняет короткий первичный отбор.

## Живые результаты

Каждый опыт начинался только при выключенном DPI. Фиксированный профиль запускался через установленную защищённую службу, после измерения останавливалось строго его поколение, затем подтверждалось выключенное состояние.

| Профиль | Результат обязательных проб | Время сетевой части |
| --- | --- | --- |
| Discord `discord_tls_multidisorder_alt` | API HTTP 200, WSS Hello, целая PNG CDN; 4 успешных опыта | 0,381–0,405 с |
| Discord `research_discord_tls_window_disorder` | API HTTP 200, WSS Hello, целая PNG CDN; 2 успешных опыта | 0,690–0,693 с |
| YouTube `youtube_tls` | Страница с ожидаемыми признаками и целая JPEG CDN | 1,455 с |
| YouTube `research_youtube_twitch_tls_window_disorder` | CDN прошёл, запрос страницы дал транспортную ошибку | 2,067 с |

Это результаты отдельных сетевых испытаний профилей. Полный новый турнир через UI, запуск настоящего Discord, голос и воспроизведение видео здесь не проверялись. Вывод о работе приложения требует прикладного испытания финалиста. Сборщик в это исправление не входит.

## Проверки

61 Rust-тест `protected_runtime::` прошёл, 3 live-теста по умолчанию ignored. Новые проверки: переход к доступному адресу, сохранение Host/SNI и проверки TLS-сертификата при закреплении адреса, отсутствие задержки от вспомогательной цели. 42 теста frontend/bridge и production-сборка интерфейса прошли. Live-диагностика записывает как успехи, так и отказы; успешный exit диагностического harness означает завершение опытов и очистки, а не успех каждого кандидата.
