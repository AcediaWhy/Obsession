## Разрыв в проверке конфигурации

`gateway_probe.rs` использует `tokio_rustls::TlsConnector`: настоящий HELLO/pong
после TLS подтверждает Gateway для этого пробника, но не для всех ClientHello
десктопного клиента. `flow_evidence.rs` анализирует зарегистрированные сокеты
пробника, не формы из текущего Discord NetLog. Отдельного обязательного CDN
endpoint в обычном Discord TLS quorum нет.

В shipped Lua `multidisorder` разрешает позиции по содержимому reasm_data,
потом отправляет части в обратном порядке. `midsld/sniext` зависят от конкретного
ClientHello; это место для проверки совместимости, а не доказанный дефект Lua.
Следующий инженерный шаг: подтвердить исполнение/доставку для неудачной формы,
затем проверять синтезируемую программу на нескольких формах свежего полноценного
TLS клиента и CDN. Одного успешного Rustls WSS нельзя считать доказательством
быстрого запуска реального Discord. Сохранённые публичные key shares из журнала
не использовать как постоянную замену полноценному TLS.

App/runtime/защищённый pack/конфиги не изменялись. Изменены диагностические
скрипты и документы. Безопасный parser: пять тестов; replay script: syntax check.
