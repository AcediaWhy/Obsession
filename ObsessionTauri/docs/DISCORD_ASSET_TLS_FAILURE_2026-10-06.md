# Зависание файла в составной конфигурации Discord

Реальный прогон установленного приложения завершился 6 октября в 21:02:52
(Самара, UTC+4), runId `c6fd24846fdd8386de92fbe33142b42c`. Пользователь сообщил,
что выполнил инструкции с выключенным VPN; независимая проверка сетевого пути
не проводилась. Исходная история испытаний не изменялась.

Составная конфигурация: Hostfake + MD5 для API/Gateway и файлов на discord.com,
Разбиение SNI для CDN. Три собственных поколения, 27/27 обязательных сокетов
обработали ожидаемые блоки, native send и завершение Lua-действий записаны.
Это подтверждает выполнение разделения. Два из трёх раундов прошли полностью.

## Что произошло

Во всех трёх раундах выбирался один файл `/assets/web.90d3ab34abfe98da.js`
на одном IP. Первые две выборки по 512 КиБ прошли за 385 и 550 мс
(это время нового соединения, TLS, HTTP и чтения выборки). В третьем раунде:

1. `/app` ответил HTTP 200, прочитаны 74 512 байт HTML.
2. Открылось отдельное TCP-соединение для файла к тому же закреплённому IP.
3. Его ClientHello обработал Hostfake + MD5; native отправки приняты.
4. Проверенное TLS-рукопожатие не завершилось до срока раунда. Время самой
   функции — 7 690 мс; байты файла и его HTTP-заголовки не получены.
5. Остальные обязательные функции, включая обе формы большого ClientHello,
   REST API, Gateway Hello и CDN, прошли.

HTTP 200 в старой записи функции относится к HTML. Код сохранял поле между
двумя запросами; это ошибка происхождения диагностических данных, а не успех
загрузки файла. На допуск кандидата она не влияла: результата `http_transfer`
нет, третий раунд остался неполным, применение заблокировано.

Неверный блок, смена публичного файла и смена закреплённого IP в этом прогоне
не объясняют отказ. Фаза отказа предшествует HTTP-запросу файла: ответ 404,
содержимое JS и его скорость ещё не измерялись. Полное время функции включает
поиск файла на HTML-странице; его нельзя назвать временем одного TLS-рукопожатия.

## Что пока неизвестно

Запись native send доказывает принятие вызова API движком. Она не показывает,
какие сегменты подтвердил удалённый TCP и какие TLS-данные вернулись.
В этой версии приложение не переносило `packetCapture` из ответа службы в
историю. Процесс испытания уже остановлен; эти временные данные восстановить
из существующего архива нельзя. Поэтому потеря сегментов, TLS-отказ и сбой
сервера/пути остаются гипотезами. Причина «Hostfake + MD5 нестабилен» пока не
доказана сравнением с контрольным профилем.

Поставляемый профиль использует `hostfakesplit:nofake2:tcp_md5`. Описание
[hostfakesplit в документации zapret2](https://github.com/bol-van/zapret2/blob/master/docs/manual.en.md#hostfakesplit)
объясняет последовательность реальных и поддельных сегментов. Само наличие
этого механизма не доказывает, что именно он вызвал наблюдаемый тайм-аут.

## Исправление диагностики

Каждое HTTP-соединение теперь отдельно сохраняет этап, время, подтверждение
TLS, собственный HTTP-статус и количество байтов. Статус страницы сбрасывается
перед новым запросом файла; суммарные прочитанные байты остаются учтёнными.

Перед остановкой поколения сохраняется уже существующее наблюдение службы:
TCP ACK, повторяющиеся последовательности, входящие байты, ServerHello, reset,
TLS alert и качество захвата. В историю проходят только точные локальный и
удалённый IP/порт принадлежащих испытателю сокетов. Чужое поколение/порт
не подмешиваются. Нет payload, SNI, cookies, токенов или входа в аккаунт.
Потери сенсора, отсутствие записей и пересечения фейковых сегментов не
позволяют автоматически вывести сетевую причину.

Пороги скорости, срок раунда и правила подтверждения не ослаблялись. ACK и
ServerHello не заменяют проверенный ответ приложения. Старый неудачный раунд
не становится успешным после исправления диагностики.

Проверка на настоящем локальном TLS-сервере воспроизводит HTTP 200 страницы,
затем второй TCP с полученным ClientHello и намеренно отсутствующим TLS-ответом.
Она проверяет точные сокеты и сохранение незавершённого этапа, а не обход DPI.
Отдельная проверка искусственными метаданными тестирует исключение чужого порта
и поколения, сохранение потерь сенсора и невозможность повысить неудачную пробу
из-за наблюдавшегося ACK/ServerHello.

Для следующего прогона: установленное обновление, VPN выключен, та же пара,
«Глубоко», «Проверить сочетание». Старый запуск ничего пересобирать не докажет;
нужны новые записи с ответной стороной. При повторении отказа сравнить с обратной
парой (Разбиение SNI для API/Gateway, Hostfake + MD5 для CDN), сохраняя отказы.
Это контроль роли первого родителя; сравнение файлов требует одинакового URL.
При отсутствии повторения отказа точная причина остаётся неопределённой.

Факты исходного прогона: `DISCORD_ASSET_TLS_FAILURE_2026-10-06.json`.
Сборка: `ZAPRET2_ASSET_DIAGNOSTICS_BUILD_2026-10-06.json`.
