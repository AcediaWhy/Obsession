## Пробел подтверждения и следующий предмет

Обычный probe.rs для Discord требует API discord.com и Gateway WSS, updater
вспомогательный. Отдельного обязательного CDN endpoint нет. Website-режим
проверяет иной набор page/JS и не является подтверждением всех CDN/ресурсов
десктопного приложения. Rustls WSS v10/json без клиентского сжатия отличается от
наблюдаемого Chromium v9/etf/zstd-stream. Эти различия требуют проверки, но пока
ни одно не назначено причиной таймаута.

Нужно сохранить полный реальный запуск при известном активном профиле, связать
Gateway с IP/этапами TCP/TLS/Upgrade/получением HELLO, отдельно проверить CDN на
том же клиентском сетевом стеке. Новый случайный набор конфигов не исправит
разрыв в подтверждении. Один сброс/таймаут ещё не доказывает смерть конфига,
срок действия, конкретный механизм ТСПУ или непрерывную ночную устойчивость.

Исправлены только диагностические скрипты: stdout/stderr локальны, окончание
записи требует нормального выхода Discord через трей, metadata обновляется
в процессе. Проверены Windows PowerShell preflight/syntax и четыре теста
безопасного разбора (удаление приватных данных, восстановление обрыва, отказ
для повреждённого ClientHello, исключение постороннего SNI). Новая запись
исправленным сборщиком ещё не запускалась; app/runtime/конфиги/сеть не менялись.
