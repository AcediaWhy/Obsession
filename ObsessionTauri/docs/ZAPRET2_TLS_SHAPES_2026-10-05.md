# Discord: отказ C02, большие TLS-запросы и проверенный профиль

Разбор пользовательских записей 4 октября и контрольные испытания в ночь на
5 октября 2026 года. Время в тексте — Самара, UTC+4.

## Что объясняет отсутствие запуска

В настройках был выбран `research_discord_tls_window_disorder` («TCP window +
перестановка · 2», C02). В двух длинных завершённых NetLog TCP к `discord.com`
и `cdn.discordapp.com` устанавливается примерно за 44–50 мс, затем TLS ждёт
около 19 секунд и завершается `ERR_CONNECTION_RESET`, без ServerHello.
Всего 43 завершённых TLS-отказа; ещё одно рукопожатие в последней записи не
завершилось до закрытия клиента. Во всех пользовательских записях разрешение
прокси показывает DIRECT. Это отказ до загрузки документов, а не измерение
низкой скорости скачивания видео.

Клиент отправляет ClientHello размером 1716–1812 байт с hybrid key share
1216 байт. Короткие Ring/Schannel запросы и даже скачивание большого JS через
такой короткий TLS проходили на C02 и A. Они не проверяли совместимость
профиля с формой запроса реального клиента.

На закреплённых адресах из свежего журнала проверили полноценные новые TLS
соединения: два больших ClientHello, с ранним и поздним SNI, затем проверка
публичного API или PNG CDN. Старые байты NetLog и сохранённые ключи не
переиспользуются. Сертификат и Finished проверяет Rustls.

| Профиль | Ранний SNI: API/CDN | Поздний SNI: API/CDN |
| --- | --- | --- |
| Zapret1 `discord_14.conf`, свежий контроль | оба проходят | оба проходят |
| C02: window + disorder | оба зависают | оба зависают |
| A: multidisorder | оба зависают | оба проходят |
| Hostfake + ACK | API проходит, CDN возвращает TLS alert | оба проходят |
| Hostfake + MD5 | оба проходят | оба проходят |

Всего испытали 14 уже установленных профилей Zapret2 и контроль Zapret1.
Из них Hostfake + MD5 проходит обе формы на API и CDN. Его дополнительные
серии больших запросов также прошли. Это локальные наблюдения на конкретном
сетевом пути, а не утверждение о любом провайдере.

## Реальный клиент

Первый контрольный запуск в 23:42 дошёл до Gateway READY за примерно
3 секунды, но использовал локальный прокси. Этот запуск исключён из
доказательств прямой работы Zapret2; по нему нельзя приписывать ускорение
профилю. Анализатор теперь отдельно сохраняет только количества DIRECT,
PROXY и неопределённых разрешений, без адресов прокси и их учётных данных.

Повтор в 00:05 выполнен с `--no-proxy-server` только у нового процесса
Discord. Системная настройка прокси не менялась. NetLog подтверждает
23 DIRECT, 0 PROXY, соединения с публичными адресами Discord:

- CDN `162.159.129.233:443`: TCP 48 мс, TLS 56 мс;
- сайт `162.159.135.232:443`: TCP 45 мс, TLS 52 мс;
- Gateway `162.159.136.234:443`: TCP 45 мс, TLS 132 мс;
- status `162.159.138.232:443`: TCP 50 мс, TLS 56 мс.

Клиент записал Gateway READY примерно через 4,05 с от запуска, затем
READY_SUPPLEMENTAL через 4,55 с. Это подтверждает авторизованное соединение
самого установленного Discord. Полная визуальная отрисовка интерфейса,
голос и длительная устойчивость отдельно не проверялись.

В испытании одновременно были включены Discord с Hostfake + MD5 и YouTube
с исходным профилем. Перед каждым испытанием DPI был неактивен; каждый
запущенный процесс обхода остановлен по своей генерации. Открытые процессы
Discord не затрагивались: запуск разрешался только при их отсутствии;
завершён только корневой процесс, созданный контрольным запуском. Поэтому
контрольный NetLog частичный; завершённые события TLS и Gateway READY
сохранены, окончание всего файла не заявляется.

## Исправление подбора

Tester version — `zapret2-functions-v4`. Discord теперь обязательно проходит
API и CDN с двумя большими свежими TLS-запросами на одном закреплённом IP
каждой цели. Один успешный layout, ServerHello без проверенного TLS,
неполный документ или короткая проба не удовлетворяют этим проверкам.
Подтверждение требует обоих сертификатно проверенных соединений и обоих
ожидаемых документов. Дедлайн раунда и лимиты чтения сохраняются; соединения
и их драйвер HTTP освобождаются при отмене.

Проверки загрузки публичных JS на 512 КиБ и сравнение скорости из предыдущего
этапа включены в эту сборку. Это не тест googlevideo и не подтверждение
воспроизведения видео.

При разнообразии кандидатов Hostfake + ACK и Hostfake + MD5 теперь считаются
разными механизмами. Иначе рабочий MD5 откладывался как похожий вариант.
Рецепты, Lua, защищённый протокол и Strategy Pack 0.12.0 не изменялись.

Свежие испытания v4:

- C02 и A не проходят большие TLS-проверки и получают неполный результат за
  примерно 3 секунды, хотя их короткие запросы и JS проходят;
- Hostfake + MD5: два полных раунда за 965–966 мс;
- третий раунд частичный: короткая CDN-проба к `162.159.129.233` получила
  тайм-аут, при этом обе большие CDN-пробы прошли. Не считать эту серию
  тремя чистыми подтверждениями. Подбор сохраняет отказ и потребует
  необходимый quorum, а не переименует его в общий успех.

В закрытом установленном Obsession изменён только сохранённый слот
Discord/TLS на `research_discord_tls_hostfake_md5` («Hostfake + MD5»).
Другие настройки сохранены; исходный файл оставлен в локальной резервной
копии, исключённой из Git. Изменение выбора не включает обход автоматически.
