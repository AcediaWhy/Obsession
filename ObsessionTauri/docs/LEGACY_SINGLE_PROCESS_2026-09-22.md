# Legacy: один процесс для выбранных категорий

## Найденный дефект

`ProtectedDataLayout::materialize_into` создавал отдельный `winws` для каждой
категории. У Discord и YouTube пересекаются захваты TCP/UDP 443. При этом
`windivert_init_filter` в zapret открывает NETWORK handle с приоритетом 0.
WinDivert доставляет пакет только одному handle на одном уровне приоритета;
для пересекающихся фильтров получатель не определён. Hostlist проверяется
позже, внутри процесса, и конфликт захвата не устраняет.

Источники:

- https://www.reqrypt.org/windivert-doc.html#divert_open
- https://github.com/bol-van/zapret/blob/master/nfq/darkmagic.c

Это подтверждённый дефект архитектуры, но не доказательство, что он является
единственной причиной недоступности Discord на конкретной сети.

## Изменение

- Один проверенный response file и один Job-owned процесс на поколение Legacy.
- Объединяются только диапазоны захвата, без расширения исходных фильтров
  профилей. Неподдерживаемые фильтры и неявная область транспорта отклоняются.
- Категории упорядочены детерминированно, Universal последняя.
- Для hostlist-auto известные/выученные домены выделяются в строгую копию
  профиля; обучающие профили идут после всех строгих, чтобы не перекрывать
  другую категорию. Пути по-прежнему проверяются через манифест и ACL.
- Snapshot сохраняет все выбранные категории и конфиги. Проверки владельца
  при восстановлении привязаны к единственному процессу, но по-прежнему
  проверяют категорию, конфиг, поколение, PID и время создания процесса.
- Одиночная категория сохраняет исходные параметры. YouTube №11 не изменён.
- Zapret2, Telegram и протокол IPC в этой правке не менялись.

## Проверки

- `cargo test --manifest-path runtime-service/Cargo.toml --lib --test legacy_combined -- --skip named_pipe::tests`:
  139 unit tests + 1 integration test passed.
- Полный первый прогон: четыре теста named pipe упали с Access denied в
  ограниченной среде. В итоговом прогоне группа из семи pipe-тестов исключена;
  они не считаются пройденными.
- `node --test scripts/audit-dpi-configs.test.mjs`: 5 passed.
- `node scripts/prepare-runtime.mjs --skip-build --dry-run-engines`:
  203 комбинации (154 пары Discord/YouTube и 49 наборов из пяти категорий),
  276 успешных проверок парсерами обоих движков. Без запуска драйвера.
  Первый ограниченный прогон не смог инициализировать winws2 (0xc0000142);
  повторный разрешённый прогон вне ограниченной среды прошёл полностью.
- Интеграционный тест проверяет один процесс для двух категорий, независимость
  от порядка выбора, проверку целостности, отклонение чужого поколения,
  очистку, повторный запуск и сохранение обеих выбранных стратегий.

## Что ещё требует проверки на сети

GET к Discord gateway/updater на старой установленной службе завершался
сбросом TLS либо таймаутом. Разрешённый пользователем A/B-замер не дал
достоверного сравнения: активное поколение и конфиг менялись параллельно,
поэтому диагностический клиент отказался останавливать чужое поколение.
Временно изменённые controls восстановления возвращены. Клиент не пишет
настройки и не завершает процессы по имени.

После установки новой сборки нужно проверить одновременно Discord и
YouTube №11, несколько циклов включения/выключения и автоподбор. Успешный
dry-run не считается доказательством обхода DPI или работоспособности звонков.
