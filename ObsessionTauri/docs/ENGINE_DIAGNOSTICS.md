# Диагностика обработки Zapret2

Lua-наблюдатель фиксирует выполнение профилей и вызовы API отправки.
Он отделён от пассивного датчика пакетов и от HTTPS-проверок доступности.

В событии `engine_diagnostics` находятся точная generation, PID, код завершения,
метаданные stdout/stderr и сводка:

| Наблюдение | Что подтверждается |
| --- | --- |
| `observer_ready` | Lua-наблюдатель загрузился в этом процессе |
| `target_profile_events` | Выполнялся профиль требуемой категории |
| `target_function_calls` | Вызвана функция стратегии этой категории |
| `target_send_api_ok` | Нативный API отправки вернул успех |
| `target_send_api_failed` | API вернул отказ или выбросил ошибку |
| `lua_errors` | Перехвачена и повторно выброшена ошибка Lua |
| `unmatched_client_hello_events` | Захваченный ClientHello не совпал с выбранными профилями |

Успех API отправки **не доказывает** выход пакета на физический интерфейс,
доставку серверу или восстановление HTTPS. Ошибки/ответы HTTP продолжают
измеряться независимыми штатными пробами. Активность YouTube или игрового
профиля не засчитывается как обработка Discord. Отсутствие событий означает
отсутствие наблюдения, а не окончательный диагноз неисправного WinDivert.

Наблюдение ограничено 120 секундами и 512 событиями Lua на процесс.
Служба сохраняет максимум 128 строк и 16 КиБ метаданных в памяти; пакеты и
блобы не дампятся, подробный debug движка не включается. Вывод читается и
отбрасывается после достижения лимита, чтобы процесс не заблокировался на pipe.
Переполнение и закрытие потока отражаются явно.

Дочерний процесс наследует только pipe вывода и NUL ввода через
`PROC_THREAD_ATTRIBUTE_HANDLE_LIST`; служебные handles не наследуются.
Чтение метаданных требует точной активной generation через типизированный IPC.
Пути, команды и дескрипторы клиент не передаёт. Наблюдатель входит в список
защищённых ресурсов и проверяется по SHA-256 перед запуском.

## Пассивное наблюдение пакетов

Штатный запуск Zapret2 не подключает старый поток событий Eyes из приложения.
Его нулевые счётчики нельзя интерпретировать как измеренное отсутствие трафика.

При диагностическом запуске с `zapret2Diagnostics: true` ответ
`GetDpiDiagnostics` может содержать `packetCapture`, привязанный к запрошенному
поколению runtime. Статус `active` означает открытие принимающего WinDivert
handle; для интерпретации данных нужны также счётчики состояния и корреляция
конкретного соединения. Ошибка запуска, недоступная DLL, незавершённая остановка,
истечение срока и завершение движка представлены отдельными состояниями.
Этот механизм не включает управление восстановлением Legacy.

Дополнительные TCP/TLS-пробы сохраняют `localAddress`. Поле
`packet_probe_correlation` сопоставляет оба адреса сокета и различает продвижение
ACK, наблюдаемые TLS-записи и RST, сохраняя признаки пробелов наблюдения
и конфликтующих перекрытий. Эти сокеты отделены от HTTPS-запросов reqwest.

Датчик использует сетевой слой с приоритетом 0. Порядок обработки относительно
winws2 и выход пакетов на физический интерфейс не подтверждены. Содержимое
пакетов находится только в ограниченной временной памяти; пакеты, SNI
и абсолютные значения TCP sequence/ACK не попадают в отчёт.

`eyes_event_stream_connected: false` указывается явно. Наблюдение пакетов
не заменяет повторную успешную проверку HTTPS.

## Проверки разработки

- `npm run test:engine-diagnostics` — контракт Lua-наблюдателя.
- `scripts/test-engine-diagnostics-luajit.py` — проверка на LuaJIT.
- Rust-тесты службы — лимиты буфера, IPC, чтение pipe и привязка к поколению процесса.
- `winws2 --dry-run` проверяет синтаксис аргументов, но не выполнение Lua-init и не работу обхода на сети.
