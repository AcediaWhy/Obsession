# Архитектура защищённого runtime

## Компоненты

Obsession разделяет интерфейс пользователя и привилегированные операции Windows. Интерфейс Tauri работает со средним уровнем целостности; установка, обновление и удаление компонентов уровня компьютера выполняются нативным worker установщика после UAC.

| Компонент | Назначение |
| --- | --- |
| `src-tauri/` | Окно, трей, пользовательские настройки и команды интерфейса. |
| `runtime-client/` | Подключение к локальной службе, проверка её подлинности и обмен запросами. |
| `runtime-protocol/` | Типизированные запросы и ответы, версия протокола и ограничения сообщений. |
| `runtime-service/` | Служба `ObsessionRuntime` под `LocalSystem`: DPI, hosts, наблюдение за runtime и правила LAN-прокси. |
| `runtime-reliability/` | Общая логика наблюдения и восстановления состояния. |
| `installer/` | Подготовка защищённой установки, транзакционные обновление и удаление. |

Telegram-прокси запускается интерфейсом без повышения прав из защищённого каталога установки. Служба выполняет только необходимую привилегированную часть, например управление правилом брандмауэра для LAN.

Устройство наблюдения за доступом и автоматического восстановления Legacy подробно описано в [документе об автообходе](AUTO_BYPASS.md).

## Модель угроз и границы привилегий

Предполагается, что посторонний код уже может работать от имени интерактивного пользователя: менять AppData, временные файлы, настройки и HKCU, подключаться к доступному IPC и создавать гонки файлов. Правильно защищённые ACL каталоги Program Files и ProgramData остаются недоступны ему для записи. Компрометация администратора или ядра находится за пределами этой модели.

Безопасность службы не зависит от того, скрыто ли имя pipe. Каждый разрешённый запрос проверяется так, как если бы его отправил посторонний код из учётной записи пользователя.

- Служба не принимает произвольные пути к исполняемым файлам, команды оболочки, рабочие каталоги или необработанные аргументы запуска.
- EXE, DLL, SYS, Lua и конфигурации привилегированного runtime загружаются только из проверенной защищённой установки.
- Пользовательские списки рассматриваются как данные. После повторной проверки служба копирует их в собственное защищённое хранилище; исходный пользовательский путь не передаётся процессу DPI.
- Процессы DPI принадлежат Windows Job Object. Остановка привязана к принадлежащему службе процессу и поколению, а не к одному имени exe.
- При ошибке проверки службы, протокола, ресурсов или ACL привилегированная операция блокируется. Возврата к запуску старых исполняемых файлов из AppData нет.

## Хранение и проверка ресурсов

| Расположение | Назначение |
| --- | --- |
| `%ProgramFiles%\Obsession` | Приложение, установочный деинсталлятор, служба и неизменяемые ресурсы. Пользователям доступны чтение и выполнение. |
| `%ProgramData%\Obsession\Runtime` | Защищённое состояние службы, подготовленные данные, журналы восстановления и транзакций. |
| `%LOCALAPPDATA%\vlarpsu\Obsession` | Пользовательские настройки, профили, журналы и кэш. |

Служба использует строгий `runtime-manifest.json` из защищённой установки. Размеры и SHA-256 проверяют соответствие ресурсов манифесту; защита самого манифеста обеспечивается установкой и ACL. Хеш не заменяет проверку подписи издателя. Нельзя считать релиз подписанным без отдельной проверки его Authenticode.

Проверки владельца, DACL и reparse points выполняются для защищённых корней и используемых дочерних объектов. Привилегированный worker не запускается из извлечённого во временный каталог пользовательского скрипта.

## IPC и доступные возможности

Транспорт — локальный Windows named pipe. Сервер проверяет данные клиента из Windows API, включая процесс, сеанс и токен; удалённые клиенты отклоняются. До передачи запроса клиент проверяет процесс сервера: `LocalSystem`, нулевой сеанс и точный защищённый путь `Obsession.Runtime.exe`. Подключение использует `SECURITY_IDENTIFICATION`.

Сообщение содержит версию, ID запроса и префикс длины. Текущая версия протокола — 4, предел кадра — 64 KiB. Неизвестные поля и неподдерживаемые значения отклоняются. Ввод-вывод имеет срок завершения, чтобы неполный запрос или нечитающий клиент не удерживал службу бесконечно.

Служба объявляет возможности после проверки установленного пакета и готовности backend. Среди них DPI Legacy, Zapret2, адаптивный Zapret2, наблюдение за событиями, управление восстановлением Legacy, hosts и брандмауэр LAN-прокси. Конкретный набор зависит от проверенных ресурсов и подключённых компонентов. `LockedBackend` возвращает пустой набор возможностей при неготовой установке. Интерфейс опирается на ответ службы, а не на наличие отдельных exe или старый флаг локального runtime.

Запросы используют ID стратегий и типизированные параметры. Backend сам выбирает проверенные ресурсы и собирает аргументы движка. События ускоряют отображение прогресса; снимок состояния остаётся источником истины.

## Изменения системного состояния

Legacy объединяет выбранные категории в один процесс. Конфигурации с `ts` могут временно включать глобальные TCP timestamps с защищённым журналом возврата; порядок и ограничения описаны в [диагностике](DIAGNOSTICS.md#процессы-legacy-и-tcp-timestamps).

Изменения hosts выполняются службой транзакционно: со снимком исходного состояния, проверкой результата и восстановлением при ошибке. Проверки доступности маршрутов не подтверждают работу всех функций AI-сервиса. Предпочтения маршрута и состояние службы передаются через типизированный IPC.

Установщик меняет защищённый пакет транзакционно и проверяет конечное дерево перед завершением. При обновлении останавливаются проверенные процессы приложения и прокси, а служба обновляется вместе с клиентом. Отмена UAC и сбой установки не должны превращаться в запуск неподтверждённых ресурсов.

Миграция пользовательских данных ограничена разрешёнными настройками и профилями. Старые исполняемые ресурсы AppData не копируются в защищённую установку. Восстановление прежних hosts и удаление старых правил брандмауэра требуют подтверждения принадлежности и сохранения посторонних данных.

Удаление разделяет компоненты компьютера и данные текущего пользователя. HKCU и пользовательские каталоги очищаются вне worker с повышенными правами; чужие профили и посторонние записи hosts сохраняются. Занятые файлы и невозможность подтвердить восстановление отображаются как незавершённая операция. Подробности — в [руководстве деинсталлятора](../installer/UNINSTALL.md).

Проверки с UAC, обновлением, аварийным завершением и реальной сетью перечислены в [списке перед выпуском](RELEASE_CHECKLIST.md). Автоматические тесты не заменяют этот прогон.
